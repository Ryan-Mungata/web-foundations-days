# Reflection

**The most difficult concept.** The hardest concept for me was asynchronous JavaScript, especially `async`/`await` and how `fetch` behaves. I did not expect `fetch` to treat a 404 as a successful request. I also got an error saying `await` was only valid in an async function, because a misplaced closing brace had ended my function too early. I overcame it by reading the Console messages carefully, testing small pieces of code in the Console, and writing one reusable `request()` function that checks `response.ok` and throws on errors. After using it for GET, POST and DELETE, the pattern became clear: show a loading message, send the request, handle success or failure, and re-enable the buttons in `finally`.

**What I would improve.** Testing my capstone showed me a weakness in the delete feature. Treating every 404 as a successful delete would hide real errors, so my code forgives a 404 only for notes created on the page, because the practice API never really stores them. I would still improve the project by connecting it to a real backend with login. My API design describes token authentication and a real database, but my client only talks to a fake server, so I could not prove that notes are really saved. I would also check the assumptions in my estimates against real usage numbers.

**What I will learn next.** I want to build the backend that my design documents describe, using a server framework and a real SQL database, and learn authentication, automated testing and deployment. I also want to keep practising two habits that saved me time: reading error messages carefully, and designing before coding.
